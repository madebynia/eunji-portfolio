# 이력서형 반응형 포트폴리오

## 목적
홈에서는 은지의 소개와 경력을 이력서처럼 빠르게 읽고, 업무와 개인 프로젝트는 각 페이지에서 자세히 탐색한다. 현재 Clinical Data 업무를 하는 사람으로 표현하며 간호 경험은 이전 경력으로 표시한다.

## 구성
- `/`: 이름, 소개, 단발 아바타, 경력 타임라인, 역량, WORK와 PROJECTS 대표 항목, 기존 공개 연락 링크.
- `/work`: Clinical Data, 업무 표준화, 문서화, 자동화 업무 목록.
- `/work/clinical-data`: 공개 가능한 기존 Clinical Data 및 표준화 경험.
- `/work/automation`: 기존 Excel 자동화 경험과 접근 방식.
- `/projects`: 업무에서 시작한 도구(DM Skills, DM Tool, DDF Knowledge), 제품(AKA, 무카랭, Nia Work), 그 밖에 만들고 있는 것(상세 페이지 없는 짧은 목록).
- `/projects/<slug>`: 프로젝트별 소개. 각 레포의 상태 문서에서 확인된 내용만 사용하며 미제공 화면·성과·데모 링크를 만들어내지 않는다.
- `/story`: 기존 커리어 이야기와 기록 유지.
- 없는 주소에는 안내 및 홈으로 돌아가는 링크 제공.

## 정체성 (2026-11-11 결정)

“도구를 만드는 Clinical DM”. 본업인 Clinical Data가 중심이고, 개발은 업무를 더 잘하려고 직접 만드는 능력으로 보여준다. 현 직장은 업계(임상시험 Data Management)와 직함만 표기하고 회사명은 쓰지 않는다. 포트폴리오에는 사용자가 고른 프로젝트만 싣는다. 개인 도구에 대해서는 실제로 확인한 기능만 쓰고, 시연과 검증은 가상 데이터로 한다. Nia Work는 회사가 승인한 범위 안에서 익명화를 거쳐 업무에 쓴다(2026-11-11 사용자 확인).

## 시각 방향
개발자 이력서형 사이드바 레이아웃, 흰 바탕과 연보라 시그니처 한 가지. 세부 기준은 `DESIGN.md`를 따른다. 역량을 백분율, 배터리, 레이더 차트로 점수화하지 않는다.

## 반응형과 이동
데스크톱은 왼쪽 사이드바 고정, 오른쪽 본문 스크롤이다. 960px 이하에서는 사이드바가 위로 올라간다. 인쇄물 이미지를 통째로 삽입하지 않고 선택 가능한 HTML 텍스트로 구현한다.

메뉴 및 항목은 실제 링크로 구현하고 각각 URL이 있는 페이지로 이동한다. 상세에서 목록으로 돌아가기, 브라우저 뒤로 가기, 직접 URL 접속을 지원한다. 기존 `/work#clinical-data`, `/work#automation`, `/work#products` 링크는 호환되도록 처리한다.

## 구현 범위와 검증
기존 React, Vite, React Router 구조와 콘텐츠를 재사용한다. 콘텐츠와 목록·상세 컴포넌트를 분리하고 새로운 백엔드는 추가하지 않는다. 키보드 포커스와 페이지 제목, 페이지 전환 시 스크롤 복원 및 초점 이동을 확인한다. 320, 768, 1024, 1440px에서 가로 넘침과 탐색을 검증한다. 목록에서 상세 이동, 없는 주소 처리, 기존 링크 호환성에 대한 테스트와 프로덕션 빌드를 실행한다.

디자인 승인 후 구현하며, 현재 공개 사이트는 아직 변경하지 않는다.

# Product Build Playbook

## 기본 루프

```text
현재 상태 확인
→ 목표 정의
→ 영향 범위 확인
→ 기존 자산 재사용
→ 필요한 경우 레퍼런스 조사
→ 최소 변경 구현
→ 테스트/빌드
→ UI/회귀 확인
→ 문서 갱신
```

## 작업 원칙

- 확인 가능한 것을 추측하지 않는다.
- 기존 기능과 콘텐츠를 이유 없이 삭제하지 않는다.
- 큰 UI 구조 변경, navigation 변경, dependency 변경, deployment 변경은 별도 브랜치에서 진행한다.
- 코드 작성만으로 완료 처리하지 않는다.
- 실행하지 않은 검증은 PASS로 기록하지 않는다.
